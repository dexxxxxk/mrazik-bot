Ответ откладывается до сетевого запроса. При недоступном канале бот подсказывает, какое право проверить. Фоновые публикации также умеют получать канал без кэша.

Если уже установлена версия 3, изменены рабочие файлы `bot.py` и `features.py`; достаточно заменить их и перезапустить бота. Полный архив позволяет обновиться с более ранних версий по инструкции ниже. Базу, токен и DATABASE_PATH оставьте прежними. Новых изменений схемы по сравнению с версией 3 нет.

Проверено 53 тестами и автономным сценарием настройки автопоста с отсутствующим в кэше каналом. Живое развёртывание ещё не выполнено.

После получения нового кода из GitHub перезапустите бота, выберите текстовый канал в `/настройка` и включите параметр автопост. Ежедневный автопост — задание дня, часовые игры включаются отдельно через `/события`.

# Обновление до Мразика 3: личные питомцы

Это обновление существующего бота. Новый Discord-аккаунт, токен и повторное приглашение на сервер не нужны.

1. Остановите бота на Bothost. Скачайте всю папку `data/` на свой компьютер. Если вы изменяли `DATABASE_PATH`, копируйте папку по указанному пути. Хранение данных на хостинге должно переживать обновление контейнера.
2. Распакуйте архив и загрузите его содержимое поверх файлов в прежнем GitHub-репозитории. Файлы `bot.py` и `requirements.txt` должны остаться в корне, рисунки — в `assets/`. Добавьте новый `personal_pets.py`; файлы предыдущих обновлений `features.py`, `activities.py`, `quiz_history.py` и `logovo_content.py` тоже нужны.
3. Сохраните прежние переменные окружения, особенно токен, `GUILD_ID` и `DATABASE_PATH`. Имя базы **`data/gnid.sqlite3` менять не нужно**. Не загружайте реальную базу и `.env` в публичный репозиторий.
4. В Bothost получите новый код из подключённого репозитория и запустите бота. При настроенном автодеплое GitHub может запустить обновление автоматически. Главный файл — `bot.py`, Python 3.11 или 3.12. Новых зависимостей нет.
5. До первого переноса существующих питомцев код создаст согласованную копию SQLite в `backups/` рядом с базой. Если копирование не удастся, миграция личных питомцев не начнётся. Внешняя копия из пункта 1 всё равно нужна: пересоздание диска хостингом удалило бы обе локальные копии.
6. Проверьте `/профиль` и `/мразик`: накопленный личный опыт, монеты и выбранный костюм должны сохраниться. Игроки получают отдельных питомцев. Старый общий опыт не раздаётся каждому; сохраняется прежний личный опыт каждого участника.
7. Выберите отдельный канал: `/настройка канал:#мразик`. Опубликуйте там `/панель` заново, чтобы обновить старые надписи на кнопках.
8. Если роли уже настроены и работают, **заново создавать их не нужно**. `/роль` проверит текущий ранг. Если автороли были выключены, `/автороли включить:True` возобновит выдачу. Для первой настройки выполните инструкцию `DISCORD_SETUP.md`.

При переходе прежним участникам один раз копируются сытость, настроение и энергия бывшего общего питомца, с учётом прошедшего времени. Затем у каждого эти показатели независимы. Выбранный наряд берётся из личного гардероба участника. Новые участники начинают с показателей 70/100, базового образа и нулевого опыта.

Последующие перезапуски эту операцию не повторяют. Старые таблицы, роли и коллекции не пересоздаются. При получении нового опыта игровая роль продолжает повышаться обычным образом.

Если запуск завершился ошибкой, сохраните её текст без токена и проверьте наличие новых Python-файлов и права записи в папку базы. Для отката остановите бота и верните прежний код. Старая версия не использует таблицу personal_pets; её общий питомец остаётся прежним. Возврат резервной копии базы отменяет прогресс после создания копии, поэтому делать это без необходимости не следует.
