# Исправление и диагностика 3.2 для установленной версии 3.1

В этом архиве только bot.py и инструкция. Замените bot.py в корне прежнего GitHub-репозитория, получите новый код в Bothost и пересоберите/перезапустите бота. features.py должен остаться от версии 3.1. Базу, данные, роли и переменные окружения не меняйте.

В логах нового запуска должна появиться строка:
Mrazik build 3.2: TextDestination + interaction deadline diagnostics

Что изменено:
- /настройка больше не читает настройки SQLite до первого подтверждения команды.
- При ошибке Unknown interaction (10062) обработчик не пытается снова отвечать через тот же недействительный запрос.
- Ошибка доставки сообщения об ошибке перехватывается, а не превращается в Task exception was never retrieved.
- При сбое подтверждения настройки записываются code, age_at_start, request_elapsed и gateway_latency, без токена.

Что это не доказывает: причина первичной задержки пока неизвестна. Исправление повторной ошибки не гарантирует устранения проблем связи хостинга с Discord. Discord требует первоначальный ответ в течение 3 секунд: https://docs.discord.com/developers/interactions/receiving-and-responding

После перезапуска вызовите новую /настройка. Если 10062 повторится, пришлите строку Setup ACK failed и время вызова. age_at_start — примерный возраст запроса по часам машины, request_elapsed — длительность попытки подтверждения, gateway_latency — задержка heartbeat, а не точный HTTP ping. При неверных часах age_at_start может быть неточным.

Дополнительно проверьте, что старый экземпляр бота не запущен на домашнем компьютере, и посмотрите свежие сообщения о связи в логах хостинга. Не сбрасывайте токен и не удаляйте бота для этой проверки.

Проверено 53 тестами и автономными сценариями просроченного подтверждения: настройки не меняются после неудачного ACK, повторного ответа нет, сбой доставки ошибки не выбрасывается наружу. На живом хостинге этот патч ещё не установлен.
